# Public fabrication regression corpus

Eight real designs, **135 imported layers**, spanning KiCad 6/8/9, Altium legacy
and X2 output, and Cadence Allegro. These are actual upstream manufacturing
exports, not files regenerated by Gerbrr. Inputs are downloaded to `target/corpus/`
and are **not bundled into the app, browser assets, or repository**.

Producer versions are read from export headers where present. LimeSDR USB's
Altium provenance is established by its accompanying PCB/OutJob sources, not a
fabricated generation header. The Cadence samples preserve the upstream `.art`,
`.drl`, `.rou` (where present), and `nc_param.txt` files; unrelated source files
and binaries are not needed to view them.

## Download, test, and open

```sh
# Download all samples and their provenance documents, checking pinned SHA-256s:
mise run corpus-fetch

# Fetch + test native import, browser byte import, and worker transfer:
mise run corpus-check

# Or fetch just one sample:
node scripts/fetch-corpus.mjs altium-limesdr-mini

# View an archive or a Cadence fabrication directory:
./target/release/gerbrr target/corpus/altium-limesdr-mini/inputs/LimeSDR_Mini_1v3_DB_DFMr0.zip
./target/release/gerbrr target/corpus/cadence-beaglebone-ai/inputs
```

In the browser, use **Open board** for the cached ZIPs or **Folder** for the
Cadence `inputs` directory. Include `nc_param.txt`: it explicitly declares NC
precision, units, and zero suppression. It is metadata, not a drawable layer.
The local static web server cannot serve the corpus cache; imports still use the
browser File API. No public or private board uploads are added.

`tests/fixtures/corpus.json` pins each repository commit, original source path,
byte count, SHA-256, licence evidence, and expected import contract. The fetcher
never executes upstream scripts or extracts archives. A modified/corrupt cache
file fails validation instead of being overwritten. Provenance documents live
separately in `target/corpus/<id>/provenance/`.

Normal `mise run check` is offline: it checks the manifest and original synthetic
reproductions in `tests/vendor_exports.rs`. The larger corpus test is explicitly
ignored until requested, and runs samples sequentially to bound peak memory.

## Hardening driven by these files

- Valid empty KiCad NPTH exports are retained without invented holes or errors.
- Comment-carried X2 file-function attributes classify renamed layers correctly.
- Altium `.G1`–`.G10` inner copper is classified/hidden appropriately. Mechanical
  `.GM14`/`.GM15` and `.GPB`/`.GPT` pad-master artwork is retained as hidden
  fabrication drawings; mechanical numbering is not assumed to mean assembly.
- Readme, pick/place, and stackup `.txt` reports are not mistaken for artwork.
  Actual `.TXT` drill files and malformed fabrication headers remain visible to
  the parser and diagnostics.
- Cadence `nc_param.txt` establishes precision explicitly, fixing the Black's
  otherwise 10×-mis-scaled full-width drill/route coordinates. Settings are scoped
  to their directory and archive; inline drill declarations still take priority.
- Older Cadence Holesize-comment tool tables and `M00` tool blocks preserve every
  hole and repeat: the AI sample has **1,927 holes across 12 tools**, matching its
  upstream quantities. The Black's drill file has **991 holes across 8 tools**.
- UTF-8 BOMs are accepted. Empty layers have sensible CLI output.

The corpus test checks layer classification, primitive counts, expected warnings,
artwork bounds, finite/index-valid geometry, drill diameters/coordinates/quantities,
and exact mesh equivalence between native, browser-byte, and worker-transfer paths.
It also compares transferred snap references and snap queries against native
results, including reconstruction of shared shape and origin indexes.
Cadence folder exports are additionally exercised as an in-memory ZIP.

All eight samples have also been opened through the actual WASM worker and both
WebGPU and WebGL2 canvases in Chromium, checking import summaries, PNG-readback
copper pixels, and absence of panics. This is a browser smoke test, not a
pixel-perfect oracle. PNG readback is used because direct WebGPU-canvas-to-2D
copies can appear black in headless Chromium even when the rendered PNG is valid.

## Known limitations and licence boundaries

- Seven samples import without warnings. **BeagleBone AI retains one deliberate
  warning** for unsupported legacy `MIA1B0` mirroring on `ASSEM_BOT.art`. That
  assembly drawing starts hidden. The test requires this warning; it does not
  suppress it or certify that drawing's rendering.
- LimeSDR mechanical-1 films contain full manufacturing drawings, not just a PCB
  perimeter. The Black's copper films also include remote annotations. Recorded
  bounds therefore describe imported artwork, **not guaranteed physical board
  dimensions**. General mechanical-layer inference/physical-outline extraction
  remains a separate improvement.
- Import contracts and cross-path equality are regression checks, not an
  independent CAM oracle. They do not prove every copper pixel is correct.
  Independent reference-render comparisons are still needed for CAM sign-off.
- Upstream designs retain their own licences and attribution requirements; the
  Gerbrr MIT licence does not relicense their artwork. Preserve upstream notices
  and consult the recorded source/terms before redistribution.
- The Black's `docs/OLD_BBB_SRM.pdf` explicitly licenses **the document** under
  CC-BY-SA-3.0, but does not separately state a copyright licence for these Gerber
  files. It is recorded as `LicenseRef-BeagleBone-design-terms`, used only for
  local testing, and must not be redistributed on the assumption that the manual
  licence applies to all artwork. The AI repository has an explicit CC-BY-4.0
  licence and is the unambiguous public Cadence alternative.

Private regression fixtures remain local and are never bundled.
